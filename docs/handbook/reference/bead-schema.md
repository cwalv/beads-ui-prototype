# Bead schema

A bead is a row in one of two mirrored tables — `issues` (committed to
Dolt) or `wisps` (dolt-ignored, kept in the working set). Both tables
share the same column set. The Go struct that travels through the API
is `Issue` at `github/gastownhall/beads/internal/types/types.go:16`.

Unless otherwise noted, schema citations point to
`github/gastownhall/beads/internal/storage/schema/migrations/0001_create_issues.up.sql`
for the `issues` table, and to
`internal/storage/schema/migrations/0020_create_wisps.up.sql` for the
mirrored `wisps` table.

## Core identity

| Column | Type | Notes |
|---|---|---|
| `id` | `VARCHAR(255)` PK | Format `<prefix>-<base36>` (e.g. `fo-7lc1i`) or hierarchical `<parent>.<n>`. Generated by `internal/idgen/hash.go`. |
| `content_hash` | `VARCHAR(64)` | SHA-256 of canonical content, recomputed on every write (`internal/types/types.go:118-171`). Excluded from JSON. |

The prefix is the project prefix (`issue_prefix` config, set by `bd
init`). Wisps get an inferred `-wisp-` infix unless an explicit prefix
is supplied.

See [explanation/the-store-architecture.md](../explanation/the-store-architecture.md)
for the issues-vs-wisps routing logic.

## Type taxonomy

`issue_type` is a `VARCHAR(32)`, not a closed enum — custom values
are first-class. The canonical built-in set is declared at
`internal/types/types.go:524-562`:

| Type | Built-in? | Notes |
|---|---|---|
| `task` | yes (default) | Default for `bd create` without `--type`. |
| `bug` | yes | `RequiredSections` adds *Steps to Reproduce* + *Acceptance Criteria* (`types.go:611-643`). |
| `feature` | yes | |
| `story` | yes | User story; `RequiredSections` includes *As a / I want / So that*. |
| `epic` | yes | Container; `RequiredSections` includes *Success Criteria*. Children attach via `parent-child` dep. |
| `milestone` | yes | Marks completion of a set of related issues; no work itself. |
| `spike` | yes | Timeboxed investigation to reduce uncertainty. |
| `chore` | yes | |
| `decision` | yes | Recorded design call; `RequiredSections` includes *Context / Decision / Consequences*. |
| `message` | yes | Mail substrate. Threaded via `thread:<id>` labels. Removed from built-ins then re-promoted in GH#1347 because inter-agent comms is too central. |
| `gate` | yes (internal) | Async coordination primitive. Carries `await_type` / `await_id` / `timeout_ns` / `waiters`. See [Gate fields](#gate-fields-async-coordination). |
| `molecule` | yes (internal) | Root bead of a poured formula. Children = steps. Carries `mol_type` / `work_type`. See [Molecule / work classification](#molecule--work-classification). |
| `event` | system-only | Asymmetric validation: rejected by `IsValid()`, accepted by `IsBuiltIn()` and `IsValidWithCustom`. System-emitted audit-trail beads (GH#1356); carries `event_kind` / `actor` / `target` / `payload`. Not creatable via strict CLI validation. |

Beyond the built-in 13, additional types can be registered via
`bd config set types.custom "name1,name2,…"`. Orchestrators ship
their own catalogs:

- **gastown** (custom): `agent`, `role`, `rig`, `merge-request`,
  `convoy`, `slot`, plus a few transient kinds (`channel`,
  `escalation`, etc.).
- **gascity** (custom): typically a smaller set;
  per-`city.toml`.

Two informal groupings help reason about the catalog:

- **Work units** (task, bug, feature, story, chore, spike) — the
  things you actually do.
- **Containers** (epic, milestone) — roll-ups that group work via
  `parent-child` deps.
- **Coordination** (gate, message, decision) — sync primitives
  between agents or humans.
- **Workflow artifacts** (molecule, event) — runtime / system-emitted
  beads, primarily for orchestrators to read.

These groupings are not enforced in code — they're conceptual aids
for UI design and documentation. `IssueType.IsValid()` returns true
for all 12 work + coordination + workflow types; `IsBuiltIn()` adds
`event`.

## Time-based scheduling

| Column | Go field | Behavior |
|---|---|---|
| `due_at` | `DueAt` | `bd list --overdue` filters where due_at < NOW() and not closed. |

## Compaction metadata

Set by the AI summarization compactor (`internal/compact/`):

| Column | Go field |
|---|---|

| `compacted_at` | `CompactedAt` |

## Messaging and ephemerality

| Column | Default | Go field |
|---|---|---|
| `sender` | `''` | `Sender` |
| `ephemeral` | `0` | `Ephemeral` |
| `no_history` | `0` | `NoHistory` |
| `wisp_type` | `''` | `WispType` |

`ephemeral` and `no_history` are mutually exclusive
(`types.go:254-256`). Either flag routes the bead to the `wisps` table.
See [explanation/the-store-architecture.md](../explanation/the-store-architecture.md)
for what each implies.

`wisp_type` selects a TTL band for automatic compaction:

| WispType | TTL |
|---|---|
| `heartbeat` / `ping` | 6h |
| `patrol` / `gc_report` | 24h |
| `recovery` / `error` / `escalation` | 7d |

## Context markers

| Column | Default | Go field |
|---|---|---|
| `pinned` | `0` | `Pinned` (bool) |
| `is_template` | `0` | `IsTemplate` |

**Warning**: the `pinned` bool column is *not the same* as
`status='pinned'`. Status `pinned` causes views to skip the row like a
closed bead; the `pinned` bool is a separate "persistent context marker"
flag that no built-in view consults. See the `pinned` entry in
[../../gaps-audit.md](../../gaps-audit.md) (§B5).

`is_template=true` marks a proto — included in
`.beads/molecules.jsonl`, excluded from `bd list` by default.

## Gate fields (async coordination)

| Column | Default | Go field |
|---|---|---|
| `await_type` | `''` | `AwaitType` |
| `await_id` | `''` | `AwaitID` |
| `timeout_ns` | `0` | `Timeout time.Duration` |
| `waiters` | `''` | `Waiters []string` |

Populated when `issue_type == "gate"`. `await_type` values:
`gh:run`, `gh:pr`, `timer`, `human`, `mail`, `bead`. The `bead` type is
currently non-functional (`cmd/bd/gate.go:726-734`). `gate` is a
built-in `IssueType` — it passes `IssueType.IsValid()` at
`internal/types/types.go:556-562` (alongside `molecule`, both flagged
in source as "internal types" intended for orchestrator coordination
rather than direct human work). No `bd config set types.custom`
registration is required.

## Molecule / work classification

| Column | Default | Go field |
|---|---|---|
| `mol_type` | `''` | `MolType` |
| `work_type` | `'mutex'` | `WorkType` |

`MolType` is one of `swarm`, `patrol`, `work` (default) —
`internal/types/types.go:649-652`. `WorkType` is `mutex` (one worker)
or `open_competition` (many submit, buyer picks) — `types.go:697-700`.

## Vestigial columns

These exist in the schema but are not in the `Issue` Go struct or
`IssueSelectColumns`:

- `hook_bead`, `role_bead`, `agent_state`, `last_activity`, `role_type`,
  `rig`

Legacy HOP fields from an earlier schema. Migration `012_drop_hop_columns`
removed `quality_score` / `crystallizes` but missed these. Do not build
against them — orchestrators that use `hook_bead` use it as a
description field, not the column. See
[../../gaps-audit.md](../../gaps-audit.md) §V1.
