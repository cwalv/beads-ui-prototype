# `bd prime` contract

`bd prime` emits AI-optimized session-start context for agent hooks.
It's wired into Claude Code, Gemini CLI, and similar AI tools via the
recipe-installed hooks (Cursor, Claude, etc. — see
`internal/recipes/recipes.go`).

Implementation: `github/gastownhall/beads/cmd/bd/prime.go`
(639 lines).

## Design goals

- **Silent-fail.** If prime can't run (no DB, missing recipes, I/O
  error), it exits 0 with no output. The agent session never breaks
  because of beads.
- **Injectable.** Output is markdown that an agent can consume directly
  as context.
- **MCP-aware.** Detects whether the caller is an MCP server; if so,
  emits a brief, structured variant (no bulky prose).
- **Overridable per-project, per-clone, and globally.**

## Invocation

Wired to `SessionStart` hooks by `bd setup` for supported tools:

```json
{
  "hooks": {
    "SessionStart": [
      {"command": "bd prime"}
    ]
  }
}
```

The typical integration calls `bd prime` with no arguments.

## Flags

From `prime.go:163-169`:

| Flag | Purpose |
|---|---|
| `--full` | Force CLI (verbose) mode, ignoring MCP detection. |
| `--mcp` | Force MCP (brief) mode. |
| `--stealth` | No-git-ops session-close protocol. Also triggered by `no-git-ops: true` in config. |
| `--export` | Emit the default content, ignoring `PRIME.md` overrides. Useful for creating a starting point. |
| `--memories-only` | Emit only the persistent-memories section (for compact hook contexts). |
| `--hook-json` | Wrap output in the SessionStart hook JSON envelope (Claude Code, Gemini CLI, Codex). Stdout becomes a single JSON object with `hookSpecificOutput.additionalContext` carrying the prime body. |

## Override chain

`prime.go:116-144`. Resolution order (first file found wins):

1. `./.beads/PRIME.md` (cwd; clone-specific).
2. `<resolvedBeadsDir>/PRIME.md` (shared workspace).
3. `~/.config/beads/PRIME.md` (global; `resolveGlobalPrimePath`
   `prime.go:33-49`).
4. Default content generated by `outputPrimeContextWithOptions`.

If any override is present and `--export` isn't set, prime prints it
verbatim and exits. Otherwise the default preamble is generated.

## MCP auto-detection

`isMCPActive` at `prime.go:194-232` reads `~/.claude/settings.json`. If
any key under `mcpServers` contains `"beads"` (case-insensitive), MCP
mode activates. MCP mode is brief:

- Skips redundant narrative.
- Truncates memory values to ~150 chars each
  (`formatMemoriesForPrime` `prime.go:340-345`).
- Uses structured markdown that MCP tools can parse.

## Memory injection

Memories stored via `bd remember` (at `kv.memory.<slug>` in the
`config` table) are automatically appended at the bottom of the
preamble.

Full content in CLI mode. MCP mode truncates to ~150 chars per value.

See [bd-commands.md](bd-commands.md#collaboration-primitives) for
`bd remember / memories / recall / forget`.

## Linear auto-pull

Before emitting context, prime calls `maybePullStaleLinearData`
(`prime.go:357-402`). If `LINEAR_API_KEY` env var or
`linear.api_key` config is set AND the local Linear data is older
than `linear.DefaultStaleThreshold`, prime shells out to
`bd linear sync --pull --json` and reports the pull count on stderr.
Pull failures are swallowed silently.

## Default content (CLI mode)

`outputCLIContext` at `prime.go:451-639`. Sections, in order:

1. **Truncation directive** — one-line preamble telling the agent to
   read the full persisted hook output if its host truncated stdout.
2. **Header** — `# Beads Workflow Context` + context-recovery note.
3. **Redirect notice** — if `.beads` is redirected to another clone.
4. **Persistent Memories** — all memories in full (omitted if none).
5. **SESSION CLOSE PROTOCOL** — checklist whose content varies by
   stealth-mode / ephemeral-branch / `no-push` / local-only state.
6. **Core Rules** — workflow rules (claim before code, no MEMORY.md,
   etc.).
7. **Essential Commands** — bucketed reference: Finding Work,
   Creating & Updating, Dependencies & Blocking, Sync &
   Collaboration, Project Health, Quality Tools, Lifecycle &
   Hygiene, Structured Workflows.
8. **Common Workflows** — Starting / Completing / Creating dependent
   work snippets.

The default does NOT embed live `bd ready` output — agents are told
to run `bd ready` themselves.

## Default content (MCP mode)

`outputMCPContext` at `prime.go:405-448`. Sections, in order:

1. Truncation directive.
2. `# Beads Issue Tracker Active` header + redirect notice.
3. Memories (compact, one line per memory, truncated to ~150 chars).
4. SESSION CLOSE PROTOCOL (single-line variant).
5. Core Rules (compact bullet list).

No live counts of ready / in_progress / blocked are emitted.

## Example override

A project-level `PRIME.md` replacing the default:

```markdown
# Session context (custom)

- Workspace: ourcompany-backend
- Current sprint: 2026-Q2-sprint-3
- Open PRs: see https://github.com/ourcompany/backend/pulls

## Today's focus

- Ship the auth v2 migration.
- Unblock code review for `bd-abc123` (API rate limiting).
```

Place at `.beads/PRIME.md`. On every agent session start, this replaces
the default preamble.

## Stealth mode

`--stealth` or `no-git-ops: true` in config suppresses git-related
instructions in the output. Use when sessions shouldn't touch git (e.g.
CI agents that should only read).

## Failure modes

From `prime.go:84-97` (no workspace) and `prime.go:150-158`
(output error):

> Silent fail on error is a deliberate design choice. No stderr output,
> exit 0. This enables cross-platform hook integration.

Under `--hook-json`, the silent-exit path still emits a valid empty
JSON envelope (`prime.go:93-95`, `154-156`) so the hook host never
receives malformed stdout.

If prime crashes internally, the SessionStart hook succeeds and the
agent starts without beads context. The agent can still run `bd ready`
manually.

## Orchestrator layering

Both gastown and gascity install their own SessionStart hooks on top
of (or instead of) `bd prime`:

- **Gastown** installs `gt prime` as the session-start hook
  (`internal/cmd/prime.go`); it renders role-specific context from
  embedded templates plus a call-out to relevant beads. Bypasses
  `bd prime` entirely in gastown-managed sessions.
- **Gascity** installs hooks per agent via `gc init`; each agent's
  prompt template embeds context directly via Go templates
  (`internal/templates/`). Does not typically shell out to `bd prime`
  in agent sessions.

For a bare beads setup (no orchestrator), `bd prime` is the canonical
session-start contract.
